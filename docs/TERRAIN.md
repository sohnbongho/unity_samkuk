# 전투 맵: 성마다 다른 지형과 지형 오브젝트 (Step 12-6, 지형 이동 12-7)

내정에서 어느 성을 공격하러 출진하느냐에 따라 **전투 맵이 달라집니다.** 이전에는 바닥에 지형 색을 한 겹 덮을 뿐이었고, 이제는 **지형별 바닥 타일 + 나무/바위/풀 같은 지형 오브젝트**가 맵 전체에 흩뿌려지며, 같은 지형이라도 **성마다 구성이 조금씩 다릅니다.**
타이틀의 **[시작]**(성 없이 시작한 판)도 빈 평지가 아니라 **평야 + 강이 있는 고정 맵**입니다(`TerrainMap.CreateFreeBattle`).

## 맵이 정해지는 방식

| 요소 | 정하는 것 |
|---|---|
| **바닥 타일** | 공격 대상 성의 **지형**(평야/초원/산악/강변/남방/황토) |
| **소품 종류** | 지형별 5가지 (예: 평야 = 나무, 덤불, 풀, 꽃, 바위 / 산악 = 소나무, 바위, 큰 바위, 덤불, 그루터기) |
| **소품 밀도** | 지형 기본값 x 성마다 0.8 ~ 1.3 (도성은 +10%) |
| **무리** | 숲, 풀밭, 바위 더미처럼 같은 소품이 한곳(반지름 약 2.3)에 3~7개 모여 있는 곳이 칸마다 1개 안팎 (밀도에 비례) |
| **바닥 얼룩** | 그늘진 곳, 볕 드는 곳, 마른 흙(산악은 드러난 돌바닥)처럼 바닥색이 은은하게 다른 둥근 얼룩이 칸마다 평균 3.5개 (성마다 0.7~1.3배). 코드로 만든 부드러운 둥근 그림(`TerrainDecals`)에 색만 입히므로 그림 에셋이 필요 없다 |
| **소품 비율** | 성마다 소품별 비중이 0.5 ~ 1.5배로 달라서 "어떤 나무가 많은 맵"인지가 다르다 |
| **바닥 색조** | 성마다 R/G/B 가 +-7% 안에서 조금씩 다르다 |
| **연못** | 강이 있는 성(`hasWater`)은 강 곁에 연못도 놓이고, 강변 지형은 조금 더 있다 (강 위에는 놓이지 않음) |
| **강** | 강이 있는 성(`hasWater`)과 강변 지형, 그리고 성 없이 시작한 판에 **구불구불 흐르는 강**이 있다. 방향, 굽이, 폭(±15%)이 성마다 다르고 지형마다 물색/강둑색/폭이 다르다 (황토 = 누런 황하) |
| **깃발** | 큰 성(대성)은 가끔, 도성(낙양, 장안)은 많이 꽂힌다 |

같은 성은 **항상 같은 맵**입니다(성 아이디로 정한 시드). 세계를 **12x12 유닛 칸**으로 나눠 칸마다 같은 배치를 계산하므로, 멀리 갔다가 돌아와도 같은 자리에 같은 나무가 있습니다.

## 강

- **모양**: 세계 전체에 같은 모양의 강이 **60유닛 간격으로 평행하게** 흐릅니다(사인 곡선으로 굽이침, 굽이 폭 2.5~4.5, 파장 26~40). 한 토막(128x64 그림 = 4x2유닛)을 1.5유닛 간격으로 **겹쳐** 이어 붙이고 흐르는 방향으로 눕히며, 물 밑에 더 넓은 **강둑** 토막을 깝니다(가장자리가 부드럽게 사라져 물가가 자연스럽습니다).
- **시작 위치**: 가장 가까운 강이 시작 위치에서 **약 10~17유닛** 떨어져 있어(걸으면 3~4초) 시작하자마자 물에 닿지 않고, 곧 화면에 들어옵니다. 시작 위치 주변은 항상 마른 땅입니다.
- **소품과 강**: 나무, 바위 등은 강물 위에 서지 않고, 연못도 강과 겹치지 않습니다.
- **건널 수 있지만 느리다**: 강은 막지 않고 **물 위에서 속도가 절반**이 됩니다(아래 "지형 이동").
- 검증: 3만 개 성으로 시뮬레이션해 가장 넓은 강(5유닛)에서도 시작 위치가 물에 닿지 않는 값(10~13)을 골랐고, 칸 경계에서 토막이 겹치거나 끊기지 않는 것도 확인했습니다.

## 덜 휑하게 (성 '완' 같은 강 없는 평야)

강도 연못도 깃발도 없는 평야 성(예: 완)은 소품이 칸당 9개 안팎이라 화면에 열 몇 개만 흩어져 **텅 비어 보였습니다.** 그래서 세 가지를 더했습니다 (모두 `TerrainMap` 의 상수로 조절).

- **흩뿌림 x1.4** (`ScatterBoost`): 테마 밀도에 곱한다. 테마 에셋(`Theme_*.asset`)은 그대로 둔다.
- **무리** (`ClusterPerBaseDensity`, `ClusterRadius`): 먼저 무리를 놓아 자리를 잡고 나머지를 흩뿌린다. 무리의 75% 는 같은 소품이라 "한 덩이 숲" 으로 보인다.
- **바닥 얼룩** (`PatchPerChunk`, `LayoutPatches`): 소품과 따로 계산하며(서로 겹쳐도 되는 장식) 강 곁에는 놓지 않는다. 그리기 순서는 가장 아래(`OrderPatch`).

화면에 보이는 스프라이트가 대략 2배(소품 약 20~30개 + 얼룩)로 늘었다. 소품 총 개수가 중요한 테스트 한도(`TerrainTests` 의 풀 개수)도 그만큼 올렸다.

## 지형 이동 (Step 12-7)

맵이 보기만 다른 것이 아니라 **이동에 영향**을 줍니다. 모든 곳을 똑같이 걸을 수 있으면 맵이 심심하기 때문입니다.

| 무엇 | 효과 | 대상 |
|---|---|---|
| 나무, 소나무, 야자, 버드나무, 죽은 나무, 그루터기 | **막힘** (밑동 반지름 0.26~0.35) | 플레이어, 적, 아군 |
| 바위, 큰 바위, 바위 더미, 이끼 바위 | **막힘** (0.42~1.1) | 〃 |
| 언덕, 계단밭, 유르트, 배, 깃대 | **막힘** (0.15~1.1) | 〃 |
| 강물 | **속도 절반** (테마 `riverSlowFactor`, 기본 0.5). 막지는 않아 건널 수 있다 | 〃 |
| 연못 | **속도 절반** (가운데 반지름 1.4, 가장자리는 얕아 그대로) | 〃 |
| 풀, 꽃, 덤불, 고사리, 갈대, 바닥 얼룩, 강둑 | 없음 (밟고 지나간다) | |
| 화살, 투사체, 경험치 보석 | 영향 없음 (나무 위로 날아간다) | |

- **미끄러짐**: 막는 소품 쪽으로 가는 속도 성분만 지우므로 비스듬히 부딪히면 **장애물을 따라 미끄러집니다.** 플레이어는 정면으로 막히면 그냥 멈추고(조작감), **적은 정면으로 막히면 목표에 가까운 쪽 접선으로 돌아갑니다**(완전히 정면이면 마리마다 정해진 쪽). 길 찾기(A*)는 없고, 나무 하나하나를 그 자리에서 비켜 가는 방식입니다. 숲이 빽빽하면 적이 늦게 오고, 강을 건너는 적은 느려지므로 **지형을 이용한 전투**가 됩니다.
- **물에서는 스스로 가는 속도만** 느려집니다. 적끼리 겹쳐 밀리는 힘과 넉백은 그대로입니다(넉백으로 강에 밀어 넣을 수 있다). 나무/바위는 넉백도 막습니다.
- **스폰과 자리**: 적은 나무 속에 스폰되지 않고(가까운 빈 자리로), 아군의 따라다니는 자리에 나무가 있으면 그 곁에 섭니다. 플레이어 시작 위치 주변(반경 2.5)은 원래 비어 있습니다.
- **맵 편집기로 고친 칸**도 같은 규칙입니다. 직접 그린 강은 폭(세로 배율)에서 느려지는 범위를 거꾸로 구합니다.
- 지형 그림이 없어 예전 색 덮개 방식으로 동작하는 판에는 지형 효과도 없습니다(`TerrainCollision.Active` 가 null).
- **물결 연출**(`WaterRippleFx`, 소품 루트에 함께 붙음): 플레이어·아군이 물에 들어가는 순간 큰 물결 두 겹 + 물방울 + 첨벙 소리(`SfxId.Splash`), 물 안에서 걸으면 발밑에 작은 물결이 0.17초마다, 서 있으면 0.75초마다 생깁니다. 적은 소리 없이 물결만 내며(마리당 평균 초당 2개, 프레임당 6개 상한) 전체 물결은 160개까지 풀로 돌려 씁니다. 그림은 코드로 만든 둥근 테를 납작하게 눌러 배경 레이어(강물 위, 캐릭터 아래)에 그립니다. 쓰러진 아군은 물결을 내지 않습니다.

### 수치 바꾸기

- **소품별**: 테마 에셋(`Theme_*.asset`)의 소품 항목 `Block Radius`(막는 반지름, 0 = 통과), `Slow Radius`/`Slow Factor`(느려지는 범위와 배율). 크기 배율(scale)이 곱해집니다. 연못/깃발은 `TerrainThemeCatalog.asset` 의 `Pond`/`Banner`.
- **강**: 테마의 `River Slow Factor` (1 이면 느려지지 않음).
- **종류별 기본값**: `TerrainPropKinds`(코드). 셋업(`Step 12-6`)은 **이동 값이 하나도 없는 테마(지형 이동 전에 만든 에셋)만** 이 기본값으로 채우고, 하나라도 있으면 사용자가 조정한 것으로 보고 건드리지 않습니다. 새로 추가된 소품은 항상 기본값을 받습니다.
- **동작 방식**: `TerrainCollision`(`Assets/Scripts/World/`)이 칸 배치에서 막는 원/느려지는 원을 뽑아 4x4 유닛 셀에 넣어 두고, `PlayerController`/`EnemyManager`/`AllyController` 가 매 틱 `SpeedFactor`(배율)와 `Resolve`(미끄러짐·밀어내기)를 부릅니다. 유니티 물리 콜라이더는 쓰지 않습니다(적 수백 마리를 이미 코드로 처리하고 있고, 테스트할 수 있어서). 테스트는 `Assets/Tests/PlayMode/TerrainCollisionTests.cs`.

## 조명 (Step 14-1, HD-2D)

전투 맵에는 세 가지 빛이 있습니다. 모두 `Hd2dSettings.Lighting`(타이틀 [조명 연출] 버튼, 저장 `hd2dLighting`)으로 한꺼번에 켜고 끄며, 게임 안에서는 **F5** 로 저장을 건드리지 않고 전후를 비교할 수 있습니다(에디터/개발 빌드). 맵 편집기 화면에는 조명을 붙이지 않습니다(`InfiniteBackground.LightingAllowed = false`, 편집 화면은 밝고 일정하게. 전투 테스트에서 봅니다).

- **시간대 색조**: 씬의 전역 Light2D 에 지형 색조 x 시간대 색조를 곱합니다(`LightingPreset`). 시간대는 성 배경 그림의 하늘(낮/해질녘/새벽)과 같습니다 — 생성기와 같은 해시·난수로 성 아이디에서 뽑습니다(`CastleMood`). 성 없이 시작한 판은 낮. 어떤 조합도 채널이 0.45 밑으로 내려가지 않아 적이 안 보이는 일은 없습니다(테스트가 지킴).
- **소품 점광원**: 빛 값이 있는 소품(`TerrainProp.lightColor/lightRadius/lightIntensity/lightFlicker/lightHeight`)은 `TerrainPropSpawner` 가 소품과 함께 Light2D(Point)를 만들고 함께 풀로 돌려보냅니다. 기본값(`TerrainPropKinds.ApplyLightDefaults`)은 **깃대 = 횃불**(따뜻한 색, 일렁임 0.35, 깃대 위 1.6유닛), **유르트 = 창의 불빛**, **연못 = 희미한 푸른 빛**이고 나머지는 빛이 없습니다. 일렁임은 펄린 노이즈라 깜빡이지 않습니다.
- **플레이어 빛**: 주인공 주변 반지름 3.2 의 약한 빛(`BattleLighting`). 어두운 시간대에도 주인공 주변은 또렷합니다.

수치는 소품별로 `Theme_*.asset`/`TerrainThemeCatalog.asset` 의 빛 값을, 전역광은 `LightingPreset`(코드)을 고칩니다. 셋업(`Step 12-6`)은 이동 값과 같은 규칙으로 **빛 값이 하나도 없는 테마만** 기본값으로 채웁니다(Step 14-1 이후 한 번 재실행 필요).

## 서 있는 소품과 월드 정렬 (Step 14-4, HD-2D)

소품은 두 가지로 나뉩니다(`TerrainProp.standing`, 용어는 `CONTEXT.md`).

- **서 있는 소품**(나무, 바위, 언덕, 유르트, 배, 깃대 = 막는 소품과 같은 집합): 캐릭터(주인공, 아군, 적)와 함께 **World 정렬 레이어**에 들어가 **발 위치(y)** 로 앞뒤가 정해집니다 — 나무 뒤로 걸어가면 가려지고, 앞에 서면 나무를 가립니다. 회전하지 않고(맵 편집기에서도), **드리운 그림자**가 붙습니다.
- **바닥 장식**(풀, 꽃, 덤불, 갈대, 고사리, 얼룩, 연못, 강): 예전처럼 배경 레이어에 눕혀 그려져 모든 캐릭터 뒤에 깔립니다. 소품끼리는 아래쪽(y가 작은)이 위에 그려집니다.

정렬은 코드가 프레임마다 값을 쓰지 않습니다. 2D 렌더러의 투명 정렬 축을 (0, 1, 0) 으로 두고(셋업 `Step 14-4`, `Renderer2D.asset`) 스프라이트의 정렬 기준점을 피벗(= 발)으로 두면 유니티가 알아서 정렬합니다(`WorldSorting`). 그래서 **캐릭터의 트랜스폼 위치 = 발 위치**이고(걷기 시트 피벗이 발, `HeroSpriteSet.FootPivot`), 지형 충돌의 밑동 원, 그림자의 시작점도 같은 점입니다.

**드리운 그림자**(`CastShadow`): 캐릭터·서 있는 소품의 그림을 검고 반투명하게 한 번 더 그리되 발에서 비스듬히 눕힙니다. 유니티 트랜스폼에 전단이 없어 "회전 → 배율 → 회전" 3단 자식으로 전단 행렬을 만듭니다(`ShadowPreset.Decompose`). 방향·길이·농도는 성의 시간대를 따르고(`ShadowPreset`, `BattleLighting` 이 정함), 배경 레이어(순서 200)에 그려져 캐릭터 아래에 깔립니다. 적이 너무 많아 무거우면 `ShadowPreset.EnemyBlob = true` 로 적만 발밑 타원으로 바꿉니다. 끄기: 타이틀 [그림자], 게임 안 F8. 맵 편집기 화면에는 그림자를 붙이지 않습니다(정렬은 같아 가려짐은 보입니다).

## 지형 오브젝트는

- 바닥 장식은 배경 정렬 레이어에 그려져 **적, 플레이어, 투사체, 경험치 보석 뒤에** 깔립니다. 소품끼리는 아래쪽(y가 작은)이 위에 그려집니다. 서 있는 소품은 위 절을 보세요.
- **플레이어 시작 위치 주변(반경 2.5)** 은 비어 있습니다. 소품끼리, 소품과 연못도 겹치지 않습니다.
- **화면 주변의 칸에만** 만들고, 멀어지면 풀로 돌려보냅니다(약 100~200개 안팎의 스프라이트).

## 작업 방법

### 그림 다시 만들기

```
powershell -File tools\terrain_art\generate.ps1                 # 전부
powershell -File tools\terrain_art\generate.ps1 -Only Jungle    # 한 지형만 (Plain/Steppe/Mountain/River/Jungle/Loess, 공용은 Shared)
```

모아보기는 `%TEMP%\terrain_sheet.png` 에 저장됩니다. 직접 그린 그림으로 바꿨다면 그 지형은 `-Only` 로 피해서 실행하세요.
가져오기 설정(스프라이트, PPU 32, Point 필터, 바닥 타일은 Repeat + FullRect, 소품은 피벗이 바닥)은 `TerrainSpriteImporter` 가 자동으로 맞춥니다. 생성기는 예전 좌표계(바닥 256, 나무 144x176)로 그린 뒤 절반으로 줄이고 도트 규격으로 다듬어 저장하므로(`PixelTools`), 그리는 코드는 그대로입니다.

### 그림 직접 바꾸기

같은 이름(`Prop_Plain_Tree.png` 등)으로 덮어쓰면 됩니다. **소품은 바닥에 닿는 점이 그림 아래쪽 가운데(아래에서 3px 위)** 에 오게 그리고, **바닥 타일은 128x128(PPU 32 = 4유닛)에 가장자리가 서로 이어지게**, 반투명 없는 도트로 그리세요(강 토막만 가장자리가 흐려도 됩니다). 다른 이름을 쓰려면 테마 에셋의 해당 칸에 직접 끌어 넣으세요(셋업은 이미 연결된 그림을 덮어쓰지 않습니다).

### 소품 추가/조정

1. `terrain.json` 의 해당 지형 `props` 에 한 줄 추가(파일 이름, kind, 색, weight, scaleMin/Max)하고 `generate.ps1 -Only <지형>` 으로 그림을 만든 뒤 `Step 12-6` 을 실행하면 **빠진 소품만 추가**됩니다.
2. 이미 만들어진 테마의 **밀도/비중 수치는 테마 에셋(`Theme_*.asset`)을 직접 고치세요**(셋업은 기존 값을 덮어쓰지 않습니다). 소품이 너무 많거나 적으면 `Props Per Chunk`, 특정 소품이 흔하거나 드물면 해당 `Weight`.
3. 새 그림 종류(kind)가 필요하면 `TerrainArt.cs` 에 그리는 함수를 추가합니다.

## 아직 없는 것 (다음 후보)

- **맵 편집기에 막는 범위(원) 표시**: 어디가 막히는지는 전투 테스트로만 볼 수 있습니다.
- **지형별 바닥 효과**: 산악 전체가 느려진다, 황토는 먼지가 난다 같은 바닥 자체의 규칙은 없습니다(소품/물만).
- **길 찾기**: 적은 나무를 그 자리에서 비켜 갈 뿐이라 빽빽한 바위 더미 사이 막다른 곳에서는 잠깐 머뭇거릴 수 있습니다.
- **성마다 고유한 랜드마크**: 성별 시드로 배치만 달라질 뿐 특정 성의 고유 오브젝트(예: 낙양의 폐허)는 없습니다.
